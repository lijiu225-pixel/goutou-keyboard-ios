# 本地聊天门控与实时气泡证据

本次借鉴 Get-OCRTextFromGPT 的聊天结构分类思路、OpenCairn 的气泡颜色证据思路。
不引入它们的云端调用、Python/PowerShell 运行时，也不复制 weixin_ocr 的固定 RGB 阈值。

- 门控：保留已有导航、输入区、消息块、首页 tab 与连续帧确认。设置、搜索、通讯录、发现页面只有在标题与至少两项独立固定控件同时匹配时，才增加明确非聊天证据。普通聊天句子中的 UI 词、单个菜单词或联系人名字不足以排除聊天。
- 实时 OCR：识字参数保持原样。按帧方向生成最多 384 像素宽、1536 像素高的临时分析图，复用截图导入已有的背景估计、气泡填充/边缘与头像扫描；只把边界、颜色类别、头像侧别附加到 OCR 观察值。
- 角色：有效气泡证据优先于文字边距。绿色只作微信自发气泡的辅助线索；位置与颜色或头像冲突时保留未确定。无像素证据或无效边界仍使用原几何判断。
- 合并：不同角色的相邻行不合并，候选进入既有稳定化、时间线和人工确认流程。颜色不创造缺失文字，也不保证所有自定义背景/主题可识别。
- 诊断：增加非聊天控件标志和气泡证据行数，仅在 App 的诊断页展示结构和计数；灵动岛继续只有状态和数量。

屏幕像素只在内存中处理，不上传、不落盘。没有新增 AI 调用、自动插字或自动发送。人工确认与自动同步的已有授权边界保持不变。

验证包含设置页误放行反例、真正 Vision 读取到文字但角色仍未确定的反例，以及深浅主题、原始像素旋转后的方向一致性、证据冲突、缺失回退、多行合并与既有十气泡回归。CI/模拟器成功不能代替重签后的 iPhone 真机验收。
