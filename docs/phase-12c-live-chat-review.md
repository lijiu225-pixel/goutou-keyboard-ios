# 阶段 12C：实时聊天 → 用户确认 → 共享给键盘

把 12B 的实时时间线接到**已经验证过的**共享链路上：

```
ScreenCaptureKit → Vision OCR → LiveChatTimeline
  → 用户点「整理当前实时聊天」→ 冻结成 LiveChatReviewDraft
  → 用户逐条核对 / 改正文 / 改归属 / 排除
  → 用户点「保存给狗头军师」→ 现有 SharedChatStore → App Group latest_chat.json
  → 键盘照旧点「读取识别聊天」读取
```

本阶段**不**自动保存、**不**自动调 AI、**不**自动插入、**不**自动发送、**不**写人物记忆、
**不**修改键盘，也**不**新增第二条数据通道。

## 实时草稿 ≠ 正式聊天

- LiveChatTimeline 是自动识别草稿；SharedChatStore 里的才是正式共享聊天，两者严格分开。
- `LiveChatReviewDraft(timeline:)` 在点击「整理当前实时聊天」的一刻**复制**当前时间线：
  之后捕获继续跑、时间线继续涨，这份草稿也不会跟着跳（用户改第 5 条时不会被换成第 6 条）。
  想带上后来新识别的消息，就返回再整理一次，得到**新的**快照。
- 进入确认页**不停止**屏幕捕获；取消确认只丢草稿，实时聊天与已共享聊天都不动。

## Review Draft 模型

`LiveChatReviewMessage{id, originalRole, role, text, isIncluded}`：

- 角色映射：`me → me`、`other → other`、`unknown → unknown`（**绝不**偷偷变成某一方）、
  `system → 默认排除`（仍然显示为「系统 / 已排除」，数据不丢，但永远不写进正式聊天）。
- 正文可以改：保存的是**用户编辑后**的文本，不会被原始 OCR 覆盖。
- 每条可以「保留 / 排除」，用来兜住 12B 偶尔漏过滤的 UI 文字。
- 草稿只放内存：不写偏好设置、不写新文件、不进 App Group。

## 保存规则

- 还有「保留 + 未确定」的消息时**拒绝保存**，提示「还有 N 条消息未确定归属，先改成「我」「对方」或排除。」
- 全部排除或过滤后没有 me / other → 「没有可保存的聊天消息。」（不会写空数组还报成功）
- 正式 messages 里 role **只能是 me / other**；system 不保存、unknown 不保存。
- 顺序严格按照确认页当前顺序，不按 role / 文本 / 几何重排。
- 保存复用**现有** `SharedChatStore`：一样的校验（条数 200 / 单条 2000 / 总长 / format / version /
  role 白名单）、一样的原子写入、一样的错误模型——没有第二套 store，也没有第二条通道。
- `updatedAt` 用**本次保存时刻**，所以键盘「30 分钟旧内容」的提示语义仍然正确。
- 成功的文案用**实际写入条数**：「已保存 N 条实时聊天，去键盘点『读取识别聊天』。」；
  失败只显示原因（沿用 SharedChatStore 的文案），不会同时出现成功提示，也不吐路径与正文。

## 与其他入口的边界

- 截图 OCR → 人工修正 → 「保存给狗头军师」那条链路**原样保留**，两个来源最终写同一个 SharedChatStore。
- 「清空实时聊天（不影响已共享聊天）」只清实时时间线与稳定化状态；截图页的「清除已共享聊天」只删共享文件。
  两者文案已经写清楚，互不越界。
- 键盘本阶段 **0 修改**：仍然由用户打开键盘 → 狗头军师 → 「读取识别聊天」，没有跨进程 hack、没有私有通知。

## 测试

`tools/LiveChatReviewCheck`（CI 的 `Live chat review contract`，纯逻辑 + 临时容器，不联网）覆盖：
timeline → snapshot、顺序保持、三种角色映射、system 默认排除、草稿冻结、
未处理 unknown 阻止保存、unknown 改 me/other/排除、改正文后保存的是改后文本、
排除与 system 不进入正式 messages、空正文 / 全排除 / 无有效消息被拒、
最终 role 只有 me / other、`updatedAt` 用保存时刻、第二个实例读到相同内容、第二次保存替换第一份、
保存失败只报失败且旧共享聊天仍在、单条超长与条数超限仍由现有校验拒绝、
草稿不写文件与偏好设置、实时识别绝不自动写共享聊天、取消 / 清空 / 清除共享聊天三者互不影响，
以及源码级检查（review 链路里没有 AI、输入代理、记忆、停止捕获这些调用）。

**阶段 12C 实时聊天确认 → SharedChatStore → Keyboard 链路尚待真机验收。**

## 真机验收步骤

1. 重签安装新 IPA，确认键盘已启用、完全访问已开启
2. 主 App →「动态识别测试」→ 开始 → 系统界面选**整屏**
3. 切到官方微信、打开**测试聊天**停留几秒 → 回主 App 看【实时聊天】
4. 点「整理当前实时聊天」→ 核对「我 / 对方 / 未确定」、正文与顺序
5. 改一条正文；有「未确定」就改成我 / 对方或排除
6. 点「保存给狗头军师」→ 确认提示「已保存 N 条实时聊天」
7. 打开微信调出狗头军师键盘 →「读取识别聊天」→ 核对正文 / 角色 / 顺序与刚才一致
8. 「使用这份聊天」→「分析这段聊天」→ 确认仍然拿到聊天分析、对方状态、3 条回复
9. 点一条回复，确认只插入输入框、不自动发送
10. 回主 App 点「清空实时聊天」：实时结果清零，但键盘那边「读取识别聊天」仍然读得到刚才保存的内容
