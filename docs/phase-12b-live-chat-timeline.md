# 阶段 12B：连续屏幕 OCR → 聊天消息 → 实时时间线

把 12A 的「一屏 OCR 文字」变成**按顺序的实时聊天时间线**：

```
屏幕帧 → Vision observations（文字 + 置信度 + 左上角原点的归一化包围盒）
  → 聊天区域过滤（顶部标题 / 底部输入栏与键盘不要）
  → 多行合并成消息块
  → 保守几何角色判断 me / other / unknown / system
  → 连续帧稳定化（默认连续 2 个有效 OCR 帧才 commit）
  → 跨帧去重 + 滚动 overlap 合并
  → LiveChatTimeline（只放内存，上限 200 条）
  → 主 App「实时聊天」实时显示
```

本阶段**不**写共享聊天、**不**更新键盘、**不**调用 AI、**不**插入、**不**发送、**不**写人物记忆。

## 坐标系统一

Vision 的 `boundingBox` 是**左下角原点**，项目内部统一换算成**左上角原点**的归一化坐标
（`LiveOCRObservation.fromVision`，只在这一处换算）。之后所有排序、区域过滤、角色判断只用这一种口径；
12A 的 `strings` / `fullText` 保持原样，`observations` 是新增字段（默认空，兼容旧调用）。

## 聊天区域过滤

`LiveChatViewportFilter`：用**中心点**判断是否落在屏幕中部的聊天区
（`topInsetRatio = 0.10`、`bottomInsetRatio = 0.28`，都在配置里）。
状态栏、聊天标题、底部输入栏与键盘、狗头军师自己的键盘文字都不会进候选。

## 多行合并

`LiveChatBlockGrouper`：按阅读顺序（先上后下、同行左到右）逐行处理，只有同时满足
**角色兼容**（me 与 other 绝不合并；unknown 与谁都可能）、**垂直间距 ≤ lineMergeDistance**、
**行高比例接近**、**水平重叠 ≥ lineMergeOverlapRatio** 才粘成同一条。
中文行直接连接，拉丁单词之间补空格；`lineMergeDistance = 0.008` 刻意比「两个独立气泡的空隙」更紧，
这样连续两条「哈哈」不会被粘成一条。

## 角色判断（只有几何）

看左右两侧**边距**而不是 centerX，所以长消息跨中线也能判对：

- 右边距 ≤ `rightAnchorTolerance` 且左边距更宽 → `me`
- 左边距 ≤ `leftAnchorTolerance` 且右边距更宽 → `other`
- 居中且很窄（≤ `maxSystemWidthRatio`，时间 / 撤回提示这类）→ `system`
- 其它（中间、几乎铺满整行）→ `unknown`

`unknown` 是一级状态：几何看不准就留在这儿，**永远不会**被静默塞进「我 / 对方」。
不研究气泡颜色、头像、背景，也不碰微信内部结构。

## 稳定化与去重

- `LiveChatStabilizer`：按**帧**计数（同一帧里三条「哈哈」只算一帧），连续
  `requiredStableObservations = 2` 个有效 OCR 帧才 commit；上一帧没出现的候选计数清零，
  保证是「连续」而不是「累计」。
- `LiveChatText.normalize` 只用于匹配（去空白、标点、统一小写），**展示与未来正文仍用原始识别文本**；
  相似度用归一化编辑距离（`similarityThreshold = 0.86`），所以「今晚吃饭吗」和「今晚吃饭吗？」
  是同一条，而明显不同的文字不会被合并。
- 相同文本但 role 不同绝不互相去重（「我：哈哈」和「对方：哈哈」是两条）。

## 滚动合并

`LiveChatTimeline.merge` 用**连续序列**找最大可靠 overlap（单条文本不可靠，尤其重复消息），
找到后：anchor 在时间线末尾 → 只把新的接在后面；anchor 在开头 → 只把更早的插到前面；
两边都不是或完全没有 overlap → **不硬拼**，记一次「不连续聊天区域」并在界面上提示。
查找范围限制在 `overlapSearchWindow = 40` 条内，避免 O(n³) 式比较。

时间线最多 `maxTimelineMessages = 200` 条（与剪贴板契约一致），超出丢最早的并计数。

## 内存与线程

- 时间线、稳定器、去重状态都只在内存里；`clearLiveChat()` 只清这些，**不停止捕获**、
  不碰共享聊天、不碰键盘；重新 Start = 新 session（generation +1，旧帧一律丢弃）。
- 线程：屏幕样本在 sample 队列、Vision 在 OCR 队列、聊天结构化（分组 / 编辑距离 / overlap）
  也在 OCR 串行队列上，只有 UI 更新回 MainActor。

## 测试

`tools/LiveChatRecognitionCheck`（CI 的 `Live chat recognition contract`，纯逻辑、不联网）覆盖：
左下角→左上角换算、顶部与底部过滤、四种角色判断（含长消息跨中线、几乎铺满整行判 unknown）、
多行合并与「一左一右不合并 / 间距过大不合并 / 阅读顺序」、第一帧不 commit 第二帧 commit、
标点抖动仍算同一条、明显不同不合并、同文本不同 role 不去重、连续三条「哈哈」保留三条、
向下滚 A/B/C/D → C/D/E/F 得 A…F、向上滚 X/Y/A/B 得 X/Y/A/B/C/D、无 overlap 不硬拼并提示、
同屏重复不重复添加、时间线 200 条上限、旧代际迟到帧不写入、清空后继续积累、
unknown 不被改写、每帧 50 条与长 timeline 的性能边界，以及「不写文件 / 不写偏好设置 /
不碰共享聊天、AI、输入代理、相册」的源码级检查。

**阶段 12B 实时聊天提取、角色判断与滚动去重尚待真机验收。**

## 真机验收步骤

1. 重签安装新 IPA → 主 App →「动态识别测试」→ 开始 → 系统界面选**整屏**
2. 切到官方微信，打开一个**测试聊天**，停留数秒，让左侧、右侧、长消息、多行消息都出现过
3. 上下各滚动一次，再回到主 App
4. 看「实时聊天」：左侧消息大体是「对方」、右侧大体是「我」，拿不准的显示「未确定」
5. 确认微信标题、顶部状态栏、键盘字母、狗头军师按键没有大量混进聊天
6. 滚动后同一消息没有大面积重复；多行气泡没有被拆成三四条；连续两条「哈哈」没被压成一条
7. 点「清空实时聊天」：时间线清零，但屏幕捕获仍在继续（计数还在涨）
8. 点「停止动态识别」：时间线不再增长
